# 5. Streaming LLM responses

Date: 2026-05-25

## Status

Accepted (v0.3).

## Context

`gakudan` v0.1 / v0.2 do all LLM I/O via the synchronous
`gakudan_llm:complete/2` callback. The entire response (text + tool
calls + usage) is returned in one map. That is fine for batch-shaped
agent workloads, but blocks two real use cases:

1. **Interactive UIs** (`gakudan_liveboard`, custom dashboards, CLI
   chat-style frontends) want token-by-token deltas so the user sees
   the assistant typing.
2. **Latency-sensitive routing** (e.g. early-stop a turn the moment the
   model emits a `@handoff` token, instead of waiting for the full
   response) requires partial-message access.

By 2026, streaming token deltas are table stakes for every serious
agent framework (LangGraph, Mastra, OpenAI Agents SDK, Pydantic-AI,
Atomic Agents). Backends without streaming look stale on every
comparison table.

The streaming contract is **separate from persistence**. v0.2 added the
checkpointer behaviour; this ADR adds streaming as an independent
callback. Backends, subscribers, and the turn worker compose them
freely.

## Decision

### Optional callback `stream_call/3`

`gakudan_llm` gains a new **optional** callback:

```erlang
-callback stream_call(request(), Opts :: map(), Subscriber :: pid()) ->
    {ok, response()} | {error, term()}.
```

Semantics:

- The backend opens its streaming connection and emits one or more
  `stream_event()` messages to `Subscriber` as bytes arrive on the
  wire.
- When the model finishes, the backend returns `{ok, Response}` with
  the **full** accumulated response (same shape as `complete/2`).
- On any transport or parse error, the backend returns `{error, Reason}`
  and may have already emitted partial events; the subscriber must
  treat the absence of a `message_stop` event as "stream truncated."

### Event shape

```erlang
-type stream_event() ::
    {gakudan_llm_stream, request_id(), event()}.

-type request_id() :: reference().

-type event() ::
    {start, #{model := binary()}}
    | {text_delta, binary()}
    | {tool_use_start, #{id := binary(), name := binary()}}
    | {tool_use_input_delta, #{id := binary(), partial_json := binary()}}
    | {message_delta, #{stop_reason => atom()}}
    | {message_stop, response()}
    | {exception, term()}.
```

`request_id()` is generated by the **caller** (turn worker) before the
call and passed to the backend via `Opts` (`#{stream_request_id =>
Ref}`). This lets a subscriber pid that listens to multiple concurrent
streams demultiplex by ref.

`start` is fired once at the top. `text_delta` may be fired many times.
`tool_use_start` precedes any `tool_use_input_delta` for that tool id.
`message_stop` is always last on success and carries the same shape
that `complete/2` would have returned. The library accumulates a
canonical response in parallel, but backends that already do this work
internally can return their version directly.

### Library-level fallback for non-streaming backends

`gakudan_llm:stream/3` (a public helper in the `gakudan_llm` module)
dispatches to `Backend:stream_call/3` if exported, otherwise falls back
to:

```
synthesize_stream(Backend, Request, Opts, Subscriber) ->
    Subscriber ! {gakudan_llm_stream, Ref, {start, #{model => Model}}},
    {ok, Response} = Backend:complete(Request, Opts),
    Subscriber ! {gakudan_llm_stream, Ref, {text_delta, all_text(Response)}},
    Subscriber ! {gakudan_llm_stream, Ref, {message_stop, Response}},
    {ok, Response}.
```

This keeps the API surface uniform: a turn worker always uses
`gakudan_llm:stream/3`. Backends opt into real streaming when they
implement the callback; otherwise the library produces a single coarse
delta. UI consumers see no transport difference.

### Per-run pubsub: `gakudan_stream`

New gen_server, one per run, sibling to the blackboard in
`gakudan_run_sup`. Holds a set of subscriber pids monitored via
`erlang:monitor/2`.

Public ops:

```erlang
gakudan:subscribe_stream(RunId)        -> {ok, reference()} | {error, not_found}.
gakudan:unsubscribe_stream(RunId, Ref) -> ok | {error, not_found}.
```

Subscribers receive `{gakudan_stream, RunId, event()}` messages. The
turn worker forwards every `gakudan_llm_stream` event it receives from
the backend into the stream pubsub, after stamping the run id and
agent id onto the event metadata.

### Wiring through the turn worker

`gakudan_turn:run/8` becomes the orchestration point:

1. Looks up the per-run stream pubsub pid from the registry.
2. Generates a fresh `Ref` for this LLM call, sets `stream_request_id`
   in `Opts`.
3. Calls `gakudan_llm:stream(Backend, Request, Opts, self())`.
4. Collects events from its own mailbox in a small loop; for each
   event, forwards it to the per-run pubsub.
5. Returns the final `Response` to the caller (run statem), same as today.

Idempotency from ADR 0004 still works: the **full response** is what
gets persisted as the step record, regardless of whether it arrived in
one event or fifty. On resume, the cached step is returned as if the
stream had completed instantly (no replay of token deltas; subscribers
who reconnect see only post-resume traffic).

### Telemetry

Three new events extend ADR 0001:

#### `[gakudan, llm, stream, start]`

`telemetry:execute/3` at the top of a streaming call.

- Measurements: `#{system_time := integer()}`
- Metadata: `#{run_id, agent_id, backend := module(), model := binary(), request_id := reference()}`

#### `[gakudan, llm, stream, token]`

`telemetry:execute/3` per text-delta. High-volume; consumers should
sample or batch.

- Measurements: `#{bytes := non_neg_integer()}`
- Metadata: `#{run_id, agent_id, request_id := reference(), event_type := text_delta | tool_use_input_delta}`

#### `[gakudan, llm, stream, complete | exception]`

A `telemetry:span/3`-shaped pair on the whole streaming call.

- Span metadata: `#{run_id, agent_id, backend, model, request_id}`
- Complete measurements (added to `duration`): `#{tokens_in, tokens_out, events := non_neg_integer()}`
- Complete metadata (added): `#{outcome := ok | error, reason => term()}`

Backends that wrap a non-streaming `complete/2` still emit the same
events; `events` will simply be small (typically 3: start, one
text_delta, message_stop).

### What this ADR does **not** lock

- Real backend impls (`gakudan_llm_anthropic`, `gakudan_llm_gemini`)
  ship in follow-up PRs. The behaviour seam is the load-bearing
  decision; converting individual backends is mechanical.
- Token-level cancellation. v0.3 streams cannot be cancelled mid-flight
  by a subscriber. The turn worker can still be killed (which closes
  the backend connection), but there is no fine-grained "stop after
  next sentence" hook. Deferred to v0.4 if asked for.

### Stability

The optional callback signature, the event shape, the
`subscribe_stream/1` / `unsubscribe_stream/2` API, and the message
shape sent to subscribers are stable from v0.3 onward and follow
semver. Adding new event variants is a minor bump if existing
subscribers can ignore unknown variants (they should pattern-match the
events they care about and discard others).

## Consequences

**Positive.**

- Liveboard / dashboard / interactive CLI consumers can finally show
  tokens as they arrive.
- The single-delta fallback means migrating to v0.3 is a no-op for
  existing users; they keep getting the same `complete/2` semantics
  unless they explicitly call `subscribe_stream/1`.
- Step-level idempotency (ADR 0004) is unchanged; persistence and
  streaming are orthogonal.
- The per-run pubsub is a natural extension of the existing per-run
  supervision tree; no new registry abstraction needed.

**Negative.**

- The library now mailbox-routes tokens through the turn worker. For
  high-throughput streams (Sonnet emitting hundreds of token deltas)
  this adds an extra hop. Acceptable: token-rate is human-scale, not
  GHz-scale.
- Subscribers that crash with a slow mailbox are detected via monitor
  and unsubscribed; no backpressure on the producer. A subscriber that
  is slower than the stream will fall behind; events past its consume
  rate are dropped on its end (mailbox grows then process exits via
  monitor). v0.3 documents this; v0.4 may add subscriber-level
  backpressure if a real consumer needs it.
- The `gakudan_llm_stream` message shape is now public API. Renaming
  events is a breaking change.
